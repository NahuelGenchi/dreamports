# Sources

The twins in this folder were written from these sources:

- Xeeynamo/sotn-decomp at 396086f (https://github.com/Xeeynamo/sotn-decomp): `src/main/psxsdk/libsnd/`, its 48 files and `libsnd_i.h`, each under the MIT License as its first line says, which each file here keeps, taken as that decompilation writes them, each named for the library here, with names of their own for the values it named by where they are in its game, every function's `static` left out so it can be a twin, two small inline helpers written as macros of the same expressions, the padding it kept in one file's zeroed values and its one function still in assembly, `_SsContDataEntry`, left out, and a few calls declared, or cast, the way a Dreamport's C needs and only where `match` doesn't build the file. The functions' names come from its `config/symbols.us.txt`, with `_SsVmSelectToneAndVag`, which that list joins to the function before it, and their sizes from the twins as `match` builds them.
- For `libsnd_types.h`, written here: the types those files use, as that project's `include/types.h` names them, and the layouts of Sony's libspu that libsnd passes to it, as its `include/psxsdk/libspu.h` writes them.
- mkst/maspsx at 4ffa8b5 (https://github.com/mkst/maspsx), under the MIT License, whose rules for Sony's assembler `match` builds these files with, divisions expanded as Sony's assembler expanded them, carried into JavaScript in `tools/ps1/maspsx.mjs`; and GNU's GCC 2.6.3, with the PlayStation's target header from decompals/old-gcc at 370040a (https://github.com/decompals/old-gcc), built on the contributor's computer and not kept here, as that project builds these files with it.
